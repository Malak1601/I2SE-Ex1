# Dataset Description

## 1. Overview

The project uses three-dimensional NRRD volumes and CSV files defining isosceles triangular or trapezoidal sampling regions. Small synthetic data supports exact-value tests and a reproducible end-to-end demo; larger MRI, Croissant, and Onion datasets support visual experiments. Coordinates are interpreted in **voxel-index space** rather than physical-space coordinates from NRRD metadata.

## 2. Small datasets included in Git

| File | Purpose |
|---|---|
| `data/demo_small.nrrd` | Reproducible synthetic volume, shape `16 × 16 × 16` |
| `data/demo_small.csv` | Two plane definitions for the small demo |
| `data/test.nrrd` | Additional small NRRD file tracked in the repository |
| `data/test.csv` | Small CSV input for testing |
| `data/Ex0_lecturer.csv` | Lecturer-based plane definitions |

The files above were verified in the submitted GitHub ZIP. Automated tests also create synthetic arrays with known values directly in memory.

Run the small demo from the repository root:

```bash
python Ex0.py data/demo_small.nrrd data/demo_small.csv results/demo_small.mp4
```

In the recorded run, the two projections had shapes `(10, 16)` and `(10, 11)` and contained 87 and 110 nonzero pixels. The output MP4 is generated by this command; it does not need to be committed for the demo to be reproducible.

## 3. MRI dataset

An MRHead MRI volume associated with 3D Slicer sample data is used for real-volume demonstrations. The repository includes:

- `data/MRHead_demo.csv` — MRI demonstration plane definitions.
- `data/mri_full.csv` — a longer MRI plane sequence.

A documented local command is:

```bash
python Ex0.py data/mri_uint16.nrrd data/mri_full.csv results/mri_full.mp4
```

This command requires the matching MRI NRRD to be downloaded or provided separately and placed at `data/mri_uint16.nrrd`. The repository includes [the MRI demonstration video](../results/mri_final.mp4) with 100 frames, but not this large NRRD input.

## 4. Croissant and Onion reference datasets

| Dataset | Reported dimensions | Reported type | CSV in Git | Plane entries |
|---|---|---|---|---:|
| Croissant | `500 × 500 × 500` | `uint8` | `data/croissant_reference.csv` | 100 |
| Onion | `256 × 256 × 130` | `uint8` | `data/onion_reference.csv` | 120 |

The repository also contains `data/croissant.csv` and `data/onion.csv`, each defining three manually selected orthogonal rectangular planes.

The large Croissant and Onion NRRD files are **not tracked in Git**. The reference videos **are** tracked:

- [Croissant reference video](../results/croissant_reference.mp4) — 100 frames at 30 encoded FPS.
- [Onion reference video](../results/onion_reference.mp4) — 120 frames at 30 encoded FPS.

The dataset dimensions and types above are from the recorded experiments; they are not inferred from the CSV files.

## 5. External data and reproduction

The assignment's supplementary dataset folder is:

[Supplementary NRRD datasets (Google Drive)](https://drive.google.com/drive/folders/1koJ83uaeMYdJt6AwvVlmMJk_wzczvmmG)

To reproduce a larger experiment:

1. Obtain the matching NRRD volume from the supplied datasets.
2. Place it in the local `data/` directory.
3. Select its corresponding CSV file from `data/`.
4. Run `python Ex0.py file.nrrd file.csv file.mp4` with the actual local filenames.

CSV entries may contain three points for an isosceles triangle or four for an isosceles trapezoid. The parser supports both coordinate-only rows and the lecturer's count-prefixed format (`3` or `4`).

## 6. Performance benchmark data

```bash
python Ex0.py --performance
```

The benchmark generates an in-memory `500 × 500 × 500` `uint8` volume; no separate benchmark NRRD file is needed. The latest recorded run measured ten warmed-up projection computations, averaging `0.00141 s` per projection (**710.91 projection FPS**). Loading, encoding, and initial Numba compilation are excluded.

## 7. Limitations

- Small synthetic data enables exact assertions but is not a substitute for testing real volumes.
- The larger datasets are distributed separately because of file size.
- CSV coordinates refer to voxel indices, not physical units.
- Projection computation FPS is distinct from end-to-end NRRD-to-MP4 processing speed.
